# Utility discovery and growth

## Objective

Keep all seven utilities useful while making their creator, ModePot and relevant sibling projects discoverable. Useful search/direct visits and repeat use also support future advertising. This change adds no ads, empty ad slots, ad SDK, fingerprinting, identity bridge or session replay, and makes no ranking, traffic or revenue promise.

## Visitor experience

Each tool's existing introductory slot now has linked ModePot and full creator attribution. Familiar headings and short operating descriptions are retained; search/social metadata is independent. A small **Explore ModePot projects / About Tugrul Guner** line appears after successful result presentation and copy/download controls. It clears on edits, replacement actions or stale results. Failed/rejected operations and partial/not-answered evidence results do not expose it as success.

Below the operating area, one relevant sibling-project introduction, related existing tools, practical steps and an example provide useful next destinations. These are sibling projects, not claimed UtilityPot implementation dependencies. Homepage art/credit, header, routes and existing operating-control IDs remain intact. Links do not gate exports or interrupt work.

Initial browser verification found real density and focus regressions. Attribution was moved into the existing introduction and original concise descriptions restored instead of loosening geometry limits. Explicitly completed results now receive focus even when already in view; scroll remains conditional. An invalid warning fixture and ambiguous header selector were corrected without changing the engine or weakening checks. The initial isolated-port analytics mismatch was a harness-origin issue; the official canonical-port suite remains authoritative. Original failed logs are retained outside the source tree.

## Verified destinations

Public roots, headings, canonical links and descriptions were independently read in the browser:

- `https://refpot.modepot.io/`: experimental embedded Python database with CRUD and explicit transactions; experimental qualification remains visible.
- `https://intpot.modepot.io/`: typed Python definitions across CLI, HTTP and MCP interfaces.
- `https://summonpot.modepot.io/`: typed APIs combining deterministic operations with bounded agent-owned decisions.
- `https://tugrul.modepot.io/`: the existing creator profile, not a new biography or republished résumé.

Family discovery targets `https://modepot.io/`. Other projects remain reachable through its directory. This is not a family-wide redesign or a claim that every utility visitor needs a Python framework.

## Measurement

The existing PostHog SDK/project and privacy configuration are retained. Read-only account inspection confirmed stored `utility_action_completed` records for the canonical utility host with tool/action/outcome dimensions, including success and failure. This establishes existing collection, not organic usage, unique visitors or correctness of every AI judgment. No private analytics records or visitor identifiers are published here.

Discovery reuses portfolio intent events:

- `modepot_clicked`: fixed canonical destination and bounded surface.
- `modepot_project_clicked`: project, fixed canonical destination, `destination_type: site` and bounded surface.
- `creator_profile_clicked`: fixed canonical profile destination and bounded surface.

Surfaces are `utility_intro`, `utility_result`, `utility_showcase`, `utility_header` and `utility_footer`. Existing header/compact-menu, footer and homepage credit variants are covered, not only new cards. The delegated listener handles primary/keyboard and middle activation, ignores right-click, leaves navigation unprevented and uses immediate beacon sending. Explicit links are excluded from autocapture. Missing/throwing analytics cannot break navigation or execution. Destinations are constants, never submitted text, output, arbitrary input URLs or link text.

New-event ingestion remains a post-deployment gate; local spy/interception success is not dashboard receipt. No dashboard, retention or conversion estimate was fabricated. Local-storage identifiers support per-site anonymous estimates; same-person cross-subdomain joining is not guaranteed and was not forced with cookies or fingerprinting. Clicks and download requests are intent; operation completions are not unique completed user tasks.

## Verification boundaries

The build runs both the existing site verifier and the seven-route discovery verifier. Browser coverage exercises mobile attribution, private success/edit invalidation, stale responses, errors, rejected graph warnings, exact telemetry, primary/keyboard/middle activation, header/footer placement, focus, export ordering and first-action geometry. Unit, real local Worker, extracted release, format, audit and dry-run gates remain required. AI fixtures are labelled fixtures, not live semantic evidence.

A separate hosted UI check is required for newly deployed presentation and unchanged backend calls. No merge or production deployment is authorized by this report. Diagram reliability is separate; this pass does not relabel the recorded production 22/23 result or certify universal model quality.
